Today's sprint focuses on two issues: shoring up the reliability of the Claude backend fallback path and improving operator visibility into running cycles. Both are small, independent, and well-scoped, so they can be worked in parallel without dependency ordering concerns.

Priority 1 is #6, the stale ANTHROPIC_API_KEY secret. Per our architecture notes, the Claude backend is CLI-first with the API key only used as a fallback — if that fallback credential is stale, we have no safety net when the CLI auth path has issues, which is a silent production risk. This should be treated as a reliability fix: verify the key is valid, refresh the secret through the standard repo-secrets → `.github/actions/write-env` → `.env` flow, and confirm the fallback path actually activates in a stubbed or dry-run test.
