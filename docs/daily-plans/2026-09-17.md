# Daily Plan — 2026-09-17

Today's sprint focuses on two internal-quality fixes to the swarm's own execution loop rather than target-repo features, since both directly cut wasted cycle time and API spend on every future run. First priority is #133 (timeout floor forgotten on deploy): the Dev agent's learned per-workspace CLI timeout floor currently lives in process memory (`tools/claude._REPO_FLOORS`), so every deploy resets it and the next cycle can repeat the exact 'first N minutes re-timing-out' pattern documented in the AGENTS.md landmines. The fix should persist floors somewhere that survives a container restart (SQLite alongside the other cycle state is the natural fit) and be covered by a test that simulates a restart.

Second priority is #135 (QA double-running the suite): today's QA phase runs the target's tests once to produce the pass/fail verdict and a second time to collect coverage, doubling suite runtime and cost for no added signal. `pytest-cov` (or equivalent) can produce both in one invocation, so this is a contained change inside `agents/qa.py` with an easy before/after check (compare QA phase duration on a real cycle).

Dependency order: #133 before #135 is not strictly required, but #133 touches the more failure-prone path (timeout handling under `tools/claude.py`) so it's safer to land and verify first while the day is fresh; #135 is a more isolated, mechanical change to the QA test-runner invocation.

Main risk: both changes touch code paths exercised by TheSwarm's own self-cycle (SELF_REPO), where a merge to main redeploys the service and kills the running cycle — per the AGENTS.md landmines this has caused lost work before. TechLead should confirm PRs land as `held_prs` for manual merge between cycles rather than auto-merging mid-run, and QA should verify the timeout-floor fix with a persistence test rather than relying on live restart behavior.
