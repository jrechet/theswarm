# Daily Plan — 2026-09-18

Today's sprint has a single backlog item, #147, so the focus is entirely on hardening the TechLead review phase: right-size the review timeout to diff size instead of a flat 180s, and make sure two consecutive review-call failures degrade gracefully (e.g. requeue or flag for manual review) instead of failing the whole cycle. This is a reliability fix, not a feature — no new user-facing surface, so risk is concentrated in cycle.py's phase budget and retry logic, both of which are load-bearing for every other cycle running today.

Priority is to land this cleanly rather than fast: recent cycles show quality gates (unit tests, coverage, security, e2e) are not reliably blocking merges even when failing, so a bug in the review phase itself is currently one of the few remaining checks with real teeth. Any change here should be tested against both a small and a deliberately large diff to confirm the timeout scales, and against a forced double-failure to confirm the cycle survives.

Main risk is scope creep: it would be easy to turn 'right-size the timeout' into a broader rewrite of the review retry/backoff logic. Keep the change narrow — timeout scaling plus a non-fatal path on double failure — and leave any deeper redesign of the review pipeline for a follow-up issue if one surfaces during implementation.

With no other backlog items ready, today's cycle should ship #147 and use any remaining capacity to surface new issues (e.g. by triaging why quality gates aren't blocking merges) rather than starting speculative work.
